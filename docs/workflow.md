# Maintenance workflow and human review

1. Keep this repository **publicly safe**: no personal account strategy, clan intel, private chats, tokens, or unapproved screenshots.
2. Record new observations in a claim with stable ID and scope.
3. Distinguish what was observed from what was inferred and from recommendations.
4. Link any derivation to all dependencies; flag weak premises.
5. Reopen an old conclusion when a patch, new account tier, or counterexample changes its applicability.
6. Review every public edit against the evidence policy.
7. If using an AI assistant, provide the repository URL and ask it to begin with `AI_START_HERE.md`, then reference claim IDs; don't expect invisible memory or automatic discovery.

`AGENTS.md` can guide compatible coding agents working on the repo, but its presence doesn't install a plugin or give outside assistants access. `llms.txt` is only an optional discovery hint.
